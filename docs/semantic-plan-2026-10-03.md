# خطة الانتقال إلى المطابقة الدلالية

تاريخ الكتابة: 2026-10-03  
السياق: الدفعة 1 = 6.5/9، الدفعة 2 = 2.0/9 على نفس أنواع الجرائم — القوائم اللفظية لا تعمم.

---

## 1. ما يكشفه الفارق بين الدفعتين

الدفعتان تحتويان على أنواع جرائم متطابقة (احتيال، تعدٍّ، إتلاف، خيانة أمانة، نهب)، لكن بصياغات مختلفة. الدفعة 1 اجتازت لأن قواعد التوسيع في `applyCriminalExpansions` ضُبِّطت بناءً على كلماتها بالضبط. الدفعة 2 فشلت لأن صياغاتها المختلفة لم تُغطَّ بعد.

**جذر المشكلة ليس الصرف العربي** — المطابقة المرنة (المؤنث، البادئات، القلب العكسي) أُضيفت بالفعل. الجذر هو **أن كل صياغة جديدة تحتاج قاعدة جديدة**، والقائمة تنمو بلا حدود. مثال:

| ما اجتاز في الدفعة 1 | صياغة الدفعة 2 المقابلة | الحالة |
|----------------------|--------------------------|--------|
| "تحطيم" → إتلاف/182 | صياغة مختلفة | FAIL (noConfidentMatch) |
| "خدع / غرّر" → احتيال/178 | صياغة مختلفة | FAIL |
| "دخل عقار" → تعدٍّ/183 | صياغة مختلفة | FAIL |

## 2. ما يوجد في قاعدة البيانات

فحص مباشر على المشروع `damzdxcutawghksuzoan` أظهر:

- **لا pgvector** — الامتدادات المثبّتة: ltree, pg_trgm, unaccent, uuid-ossp وغيرها. لا وجود لـ pgvector.
- **لا أعمدة تضمين** — أعمدة `articles` و`cases` و`laws` تحتوي على `tsvector` للبحث النصي فقط.
- **pg_trgm موجود** — يُستخدم حالياً في `match_case_candidates` و`match_legislation_candidates` لمطابقة الاستشهادات (رقم القضية + السنة + اسم المحكمة). لا يُستخدم في `analyzeCase`.
- **quick_search_v4 / universal_search_v3** — بحث نصي كامل (FTS) مع تطبيع عربي. لا دلالة في الاسترداد.
- **المقالات تحتوي على**: `content_ar`, `title_ar`, `keywords[]`, `explanation_ar` — نصوص جاهزة للتضمين لكن لم تُضمَّن.

**الخلاصة**: لا توجد بنية تحتية للتضمينات الدلالية. كل خيار يبدأ من الصفر من جانب قاعدة البيانات.

## 3. الخيارات المتاحة

### الخيار أ — تصنيف بنموذج لغوي (اللغوي يحدد المفهوم، الخريطة تحدد المادة)

```
facts text
    ↓
Claude Haiku: "ما نوع الجريمة؟" → {concept, confidence, or "abstain"/"civil"}
    ↓
CONCEPT_TO_ARTICLES[concept] → articles (لا تغيير على قاعدة البيانات)
    ↓
quick_search_v4 للقضايا فقط (كما هو)
```

- **لا هجرات في قاعدة البيانات** — فقط استدعاء API في `analyzeCase`
- **لا اختراع للمواد** — النموذج يحدد المفهوم فقط؛ الخريطة الحتمية هي السلطة الأخيرة
- **التعميم آلي** — "ابتزّ مبلغاً" و"هدّده بنشر صوره" و"طالبه بمبلغ تحت التهديد" كلها تُصنَّف ابتزاز دون حاجة لقاعدة لكل منها
- **التكلفة**: استدعاء Haiku واحد لكل طلب (~$0.001، ~300ms)

### الخيار ب — تضمينات pgvector

- تفعيل pgvector على Supabase
- توليد تضمينات لـ `title_ar + content_ar` لكل مادة في `criminal-law-1991` (≈350 مادة)
- تضمين نص الوقائع عند الطلب ثم استرداد المواد الأقرب بتشابه جيب التمام
- **ميزة**: يعمل حتى بدون أي خريطة مفاهيم
- **عيب**: هجرة قاعدة بيانات + توليد تضمينات مسبق + احتمال استرداد مواد غير ذات صلة دلالياً بطريقة خفية (false positives دلالية صعبة الاكتشاف)

### الخيار ج — pg_trgm لمطابقة العبارات (بدون LLM أو DB migration)

- استخدام `pg_trgm` للبحث عن أقرب عبارة في قاعدة مثل `legal_taxonomy` أو قاموس منسق يدوياً
- **عيب جوهري**: pg_trgm يطابق الحروف لا المعنى — "تحطيم زجاج" قد يكون أقرب حرفياً لمادة عن "تحطيم الأختام" لا عن الإتلاف الجنائي

## 4. التوصية: الخيار أ أولاً

### 4.1 البنية المقترحة

في `analyzeCase`، بعد `applyCriminalExpansions` ومباشرة قبل `analyzeCriminalConceptMap`:

```
1. applyCriminalExpansions → anyFired (كما هو)
2. إذا لم تطلق أي قاعدة حتمية (anyFired=false) →
   استدعاء LLM بنمط محدد:
     - يُعطى نص الوقائع فقط
     - يُطلب منه: {concept, confidence: 0..1} أو "civil" أو "abstain"
     - يُمنع من ذكر أرقام مواد أو أحكام
3. إذا أعاد LLM concept + confidence ≥ 0.70:
     - يُضاف concept إلى criminalTerms
     - anyFired = true → مسار CONCEPT_TO_ARTICLES
4. إذا أعاد "civil" أو confidence < 0.70 أو "abstain":
     - noConfidentMatch = true (لا يوجد استرداد)
5. applyCriminalExpansions لا تزال تعمل مستقلة —
   إذا أطلقت قاعدة حتمية، يُتجاوز LLM كلياً (السرقة/الاحتيال/الكسر بالتفصيل تبقى حتمية)
```

### 4.2 نموذج البرومبت (مسودة)

```
أنت محلل قانوني سوداني. المهمة الوحيدة: تحديد نوع الجريمة الجنائية في الوقائع.

قواعد صارمة:
- لا تذكر أرقام مواد أو قوانين.
- لا تصدر حكماً قانونياً.
- إذا كان النزاع مدنياً أو تجارياً أو أسرياً → أجب: {"type":"civil"}
- إذا كانت الوقائع غامضة أو ناقصة لتحديد جريمة بعينها → أجب: {"type":"abstain"}
- إذا تعرّفت على جريمة جنائية محددة → أجب:
  {"type":"criminal","concept":"<المفهوم>","confidence":<0.0..1.0>}
  حيث المفهوم هو أحد: سرقة | سطو | احتيال | تزوير | خيانة الأمانة |
  قتل | أذى | مركبة | مخدرات | ابتزاز | إتلاف جنائي | تملك جنائي |
  استلام مسروق | حجز غير مشروع | تعدٍّ | انتحال

الوقائع:
{facts}
```

`confidence < 0.70` → abstain. قائمة المفاهيم مقيّدة بما في CONCEPT_TO_ARTICLES فقط.

### 4.3 الحفاظ على بوابة الأمان المدنية (8/8)

ثلاثة خطوط دفاع متراكمة:

| الخط | الآلية | يحمي من |
|------|---------|---------|
| 1 (LLM) | البرومبت يصنّف مدني/تجاري/أسري → {"type":"civil"} → noConfidentMatch | تصنيف LLM خاطئ للمدني |
| 2 (حتمي) | `applyCriminalExpansions` تبقى: إذا لم تطلق قاعدة حتمية ولا LLM → noConfidentMatch | الصمت الصحيح |
| 3 (موجود) | بوابة الأمان الحالية (كل terms origin=extracted → noConfidentMatch) | لا تزال تعمل |

الخط 2 يعني: LLM لا يمكنه وحده إدخال نص مدني في المسار الجنائي دون أن تطلق قاعدة حتمية أو يرد بثقة عالية. حتى لو أخطأ LLM وأعاد concept="احتيال" بثقة 0.85 على نزاع مدني، يبقى CONCEPT_TO_ARTICLES يعيد مادة جنائية حقيقية — هذا هو الخطر الفعلي. للتخفيف:

- إضافة فحص سياقي: إذا لم تطلق `applyCriminalExpansions` **وأعاد LLM مفهوماً بثقة < 0.85** → noConfidentMatch (عتبة أعلى لمسار LLM الخالص)
- أو: تشغيل LLM فقط عندما يكون `input.caseType` غير محدد أو "جنائي" صريح

### 4.4 الامتناع عن الغامض (B2-020)

B2-020 أعاد Art. 174 على حالة مصنّفة `must_abstain_or_clarify=true`. السبب: قاعدة حتمية طلقت (ربما "أخذ" → سرقة) رغم أن النص غامض.

حل:
- LLM يتلقى نص B2-020 ويستطيع إعادة `{"type":"abstain"}` لعدم اليقين بالقصد الجنائي
- بالتوازي: قاعدة COMPOUND_CRIMINAL_EXPANSIONS تبقى، لكن عندما تطلق القاعدة الحتمية على نص يحتاج توضيحاً، يُضاف فحص LLM "هل هذا مؤكد جنائياً؟" قبل إعادة النتيجة
- البديل الأبسط: تشغيل LLM **بعد** المسار الحتمي كفحص نهائي: إذا أعاد "abstain" → يتجاوز النتيجة الحتمية

## 5. ما لا يتغير

- **قاعدة البيانات**: لا هجرات، لا أعمدة جديدة، لا تفعيل pgvector
- **CONCEPT_TO_ARTICLES**: السلطة الأخيرة لأرقام المواد — LLM يحدد المفتاح، الخريطة تحدد القيمة
- **المسار الحتمي**: `applyCriminalExpansions` يبقى ويُشغَّل أولاً — يُتجاوز LLM للحالات الواضحة (سرقة، احتيال، مخدرات) مما يوفر التكلفة والوقت
- **بوابات الأمان الموجودة**: تبقى كخط دفاع ثالث

## 7. المخاطر والتخفيفات

| الخطر | التخفيف |
|-------|---------|
| LLM يختلق أرقام مواد | البرومبت يمنع المواد صراحةً؛ الخريطة الحتمية هي المخرج الوحيد |
| LLM يُصنِّف مدني كجنائي | عتبة ثقة أعلى (0.85) لمسار LLM الخالص + الخطوط الثلاثة أعلاه |
| زمن استجابة (latency) | Haiku: ~300ms — مقبول؛ أو تشغيله بالتوازي مع applyCriminalExpansions |
| تكلفة | ~$0.001/طلب؛ يمكن تخطي LLM إذا anyFired=true (السرقة/الاحتيال لا تحتاجه) |
| تغيير سلوك موجود | LLM يعمل فقط إذا anyFired=false — لا يُعدِّل مسارات تعمل حالياً |
